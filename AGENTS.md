# AGENTS.md

mcp-portal is the self-service and administration portal of [MCP Platform](https://github.com/aiwcorpo/mcp-platform). Two
parts: `bff/` (Spring Boot, Java 25) signs users in with OIDC, keeps the session server side and serves the browser API
(C12, `portal-bff.v1`); it calls the credential broker (C4) and the gateway admin API (C5) with the client certificate
`CN=mcp-portal-bff`, and the IGA adapter (C13). `web/` (Angular 22) talks only to C12. All interfaces are governed by
`mcp-contracts` (version: `mcp-contracts.version` in `bff/pom.xml`, the tarball name in `web/package.json`).
Human docs: [README.md](README.md), [CONTRIBUTING.md](CONTRIBUTING.md), [bff/README.md](bff/README.md), [web/README.md](web/README.md).

## Commands

The BFF needs JDK 25. If `java -version` shows an older JDK, set `JAVA_HOME` first (macOS with Homebrew:
`export JAVA_HOME=$(brew --prefix openjdk@25)`). The web part needs Node 24 and npm 11.

```bash
(cd bff && ./mvnw -B verify)                       # CI job bff; no Docker needed
(cd bff && ./mvnw -B test -Dtest=ReturnPathsTest)  # one test class

cd web
CONTRACTS_FROM_NPMJS=1 scripts/contracts.sh        # fills web/.contracts/ (git-ignored); other sources: see the script header
npm ci
npm run lint && npm run i18n:check && npm test && npm run build
npx playwright install chromium                    # once
npm run e2e                                        # e2e build with MSW mocks + Playwright
npm test -- --include src/app/features/logs        # unit tests of one folder or file
```

CI job `web` runs the web steps above in that order (with `CONTRACTS_TARBALL_SHA256` pinning the tarball); job `bff`
runs `./mvnw -B verify`. On a laptop the BFF verify (about 640 tests) and `npm run e2e` take about 1.5 minutes each. `Jenkinsfile` and
`.gitlab-ci.yml` run the same commands. `scripts/build-images.sh` builds the three images from a git ref and pushes nothing.

## Layout

- `web/src/app/api/generated/`: generated from `portal-bff.v1.bundled.yaml` by `npm run generate:api`. Never edit by hand;
  regenerate after a contracts bump and commit the result with it.
- `web/src/locale/messages.xlf`: written by `npm run i18n:extract`. `messages.pl.xlf` is the Polish translation, edited by
  hand; `npm run i18n:check` fails on a missing or stale entry.
- `web/e2e/`: Playwright against the MSW mock build (contract examples, made-up user). `web/e2e-live/` runs against a live
  stack with real accounts: do not run it.
- `docs/screenshots/en|pl/`: regenerated by `cd web && npm run screenshots`, not edited.
- `bff/dev/`: IdP stub and IGA mock for local runs; `bff/.run/LocalPortal` and `LocalPortalApplication` (test sources)
  start the BFF against WireMock stubs of C4 and C5.
- `deploy/`: standalone Compose install; `deploy/certs/` stays empty in git.

## Rules

- Contract first. A change to C12, C4, C5 or C13 starts as a `proposed` entry in `CONTRACT_CHANGES.md` of `mcp-contracts`
  and needs a person's approval before it is implemented here. No hand-written API types in `web/`.
- The portal holds no list of systems, servers or resource types; they come from the gateway and the broker. Do not add one.
- The browser never receives a token or a secret. The BFF never logs, audits or returns a system secret, the login of a
  `Basic` secret, an OIDC client secret or the `reason` text of a kill switch.
- Keep the fresh MFA (step-up) on the operations listed in README, "Fresh MFA (2.0.0)"; the gateway and the broker check
  `auth_time` and `acr`/`amr` of the token again. The BFF refuses bodies over 64 KB on `/api/v1/admin/**` before reading them; keep that order.
- Interface texts are English, through `$localize` with an id, plus the Polish entry in `messages.pl.xlf`.
- Every `FROM` and `*_IMAGE` arg in `Dockerfile` is pinned by `@sha256:` digest; the release workflow fails otherwise.
- `bff/pom.xml` and `web/package.json` carry the same version, which must equal the release tag. Exact versions in
  `package.json` (no ranges).
- `CHANGELOG.md` has no "Unreleased" section. Ask the person which version heading a user-visible change goes under.

## Boundaries

Do not do any of this without a person's explicit yes: change versions, tag, release, push to main, publish images (they go
to ghcr.io only, via `release.yml`), run `e2e-live` or anything else against a running stack, Keycloak or broker, or use
real user accounts. Never commit secrets, tokens, keystores, `.env` files, `web/.contracts/`, internal host names or IP
addresses. Tests and screenshots use the contract examples and made-up data only.

## Pull requests

One change per PR. Commit subject in English, imperative, up to 72 characters; the body describes the change, not the
process. Tests go in the same commit as the code they cover. Both the BFF verify and all web steps must pass. Update
README or `bff/README.md` (configuration table) when behaviour or settings visible to operators change, and the
screenshots when a pictured screen changes. See [CONTRIBUTING.md](CONTRIBUTING.md).
